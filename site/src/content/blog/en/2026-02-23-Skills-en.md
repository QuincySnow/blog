An effective AI coding workflow is not another package to install. It is the assistant reading the right `SKILL.md` when it needs one. A Skill is a reusable workflow instruction: it tells coding agents such as Claude Code and OpenCode how to approach a particular technology, check, or delivery process. It is not an npm or Bun dependency, and it should not be treated like something that must always be fully installed in a lockfile.

This guide uses the [ECC](https://github.com/affaan-m/ECC) Skills collection and the [Skills CLI](https://github.com/vercel-labs/skills), which maintains the installation workflow. This blog recommends running the CLI with Bun's `bunx`: inspect the available Skills first, then install the ones that fit your agent and project.

## Inspect ECC Skills Before Installing

List the Skills available in the repository first. Do not skip this step just because a full-install command exists.

```bash
# Inspect the repository before installing anything
bunx skills add https://github.com/affaan-m/ECC --list

# Install all ECC Skills
bunx skills add https://github.com/affaan-m/ECC --skill '*'
```

`--skill '*'` installs the repository's full Skills selection. It is useful when you want the complete set, but inspect the list first and confirm that its workflows fit your agent, tools, and project.

## Choose the Runner and Scope You Need

`bunx` is the preferred runner on this blog. If your environment uses npm or pnpm, these installation commands are equivalent:

```bash
npx skills add https://github.com/affaan-m/ECC --skill '*'
pnpm dlx skills add https://github.com/affaan-m/ECC --skill '*'
```

A full install is not the only option. To install one Skill for a particular agent, use the supported selective-install form:

```bash
bunx skills add https://github.com/affaan-m/ECC --skill <skill-name> -a opencode
```

Replace `<skill-name>` with a name chosen from the inspected list, and replace `opencode` with the agent you actually use. Not every Skill applies to every agent or project. Install the portion that solves the workflow problem in front of you.

## Add Rust Skills for Rust Projects

For a Rust project, you can add [Rust Skills](https://github.com/leonardomso/rust-skills) alongside the ECC workflow:

```bash
bunx skills add https://github.com/leonardomso/rust-skills --skill '*'
```

This is a supplementary, Rust-specific installation, not a replacement for ECC. Whether to add it still depends on whether the project needs those Rust-focused workflows.

## Update Deliberately

Skills change. Review the scope your project needs before and after updating, and keep your normal engineering verification in place. For this Bun-based project, use:

```bash
# Recommended for this Bun-based project
bunx skills update

# Equivalent runners
npx skills update
pnpm dlx skills update
```

An update does not replace code review or the repository's own quality gates. Skills are reusable instructions for how an assistant carries out work; formatting, linting, and tests still validate the resulting changes.

## Quick Checklist

- [ ] Inspect the available Skills first
- [ ] Install only the Skills your current agent and project need
- [ ] Add Rust Skills when the project is Rust
- [ ] Update deliberately instead of blindly upgrading everything
- [ ] Continue to run the repository's own formatter, linter, and tests
